# Plan: Streamline the music-video pipeline and site pages
## 4 October 2026 | For Mark's approval before any code changes

**Why:** we built System Prompt, CVE Carnival and Get Gone on the fly. Three videos in, the pipeline only really knows about one song. The site has a copy-pasted page per video, and two videos can't be rebuilt from this repo at all. With Weight of Zero and the three Shorts videos queued, a new video should mean **adding data plus scene code, not wiring.**

**Goal:** a new video takes:
- one folder in `video/`;
- one entry in the registry;
- zero new site page files.

---

## 1. Multi-song Remotion workspace (do first)
**Problem:**
- `video/src/lib/timing.ts` hard-imports System Prompt's JSON.
- `Root.tsx` registers one composition.
- `package.json` has per-song script names.

**Change:**
- `video/src/lib/song.ts`: a `makeSong(data)` factory (scenes, words, beats, shots and ledger to typed helpers: `activeLine`, `beatPulse`, `clipReady`, `totalFrames`…), plus a `SongContext` so `Captions`, `Clip`, `ShotSlot` and `Scary` read the current song from React context instead of a module import.
- `video/src/videos/{slug}/` per video: `index.tsx` (the composition), `Thumb.tsx`, and any scene components that are truly one-off. `SystemPrompt.tsx` moves to `videos/system-prompt/`, behaviour unchanged.
- `video/src/songs.ts`: the static registry (Remotion needs static imports). Each entry has id, slug, component, thumb and format.
- `Root.tsx` loops the registry: a composition plus a thumbnail Still per song.
- **Formats:** `FORMATS = { wide: 1920x1080, tall: 1080x1920 }`. `Terminal` and `Captions` take sizing from the format, ready for the Shorts.
- **Scripts:** a single `node scripts/video.mjs <render|preview|thumb|still> <slug> [--frame N]` replaces the per-song npm scripts. It also copies the finished thumbnail to `../public/video/{slug}/thumbnail.jpg`.
- `sync-assets.mjs` reads audio paths from the registry instead of a hardcoded list.

**Check:** System Prompt renders frame-identical spot checks (frames 90, 870, 1950, 3960) before and after the refactor.

## 2. Shared visual kit
**Problem:** reusable pieces live inside `SystemPrompt.tsx`: the cold open, prompt badge, swap and morph framing, end card and beat glitch.

**Change:**
- Move the reusable pieces to `video/src/kit/`.
- New pieces as videos need them (Weight of Zero adds `Dashboard`, `Gauge`, `Redact`, `ProgressBar`, `TypedLine`, `VhsTimecode`, `Zine`).
- **Palettes per song** in `scenes.json` (`meta.palette`), not hardcoded in `theme.ts`.

**Rule:** a video file should read like a shot list: scene components plus props.

## 3. One data folder per song, with metadata in one place
**Problem:** title, artist, album and accent are typed twice: in `src/data/music-videos.ts` and in each `scenes.json`.

**Change:** `video/data/{slug}/` always has the same shape:
```
scenes.json      meta (title, artist, album, albumHref, track, accent, palette, credits) + concept/rules/cast/scenes
stills.json      still prompts (refs: ["base"])
shots.json       shot prompts
ledger.json      every paid call (generated)
timing/          words.json, beats.json (generated by analyze.py)
```
- `src/data/music-videos.ts` keeps only the **YouTube-side** fields (`slug`, `youtubeId`, `released`, `runtime`, `poster`, `cut`, `page`) and merges `meta` in from the scene book at build time.
- A typed `scenes.schema.ts` (zod or plain TS types) checked by `npm run typecheck` in `video/`, so a malformed scene book fails loudly.

## 4. One making-of page for every video (site)
**Problem:** `src/pages/music/video/{system-prompt,cve-carnival,get-gone}.astro` are about 330 lines each and almost identical.

**Change:**
- `src/pages/music/video/[slug].astro` with `getStaticPaths()` over `MUSIC_VIDEOS` (excluding alternate cuts that point at a parent `page`).
- The scene book is loaded via `import.meta.glob('../../../../video/data/*/scenes.json', { eager: true })`.
- Sections render **only if the data exists:** stills (`book.stills`), cast, timeline, scene book, alternate cuts, and credits (new: e.g. "words: Claude Opus 4.6 / picture: Claude Opus 5.5").
- Page-specific CSS moves to one shared stylesheet. URLs stay identical (`/music/video/system-prompt` etc.), so no broken links.
- The three old files are deleted.
- `YouTubePlayer` gets `aspect: '16:9' | '9:16'` from the registry entry, for the Shorts videos.

**Check:**
- `npm run build`;
- diff the built HTML of the three existing pages before and after: same content, same URLs;
- preview at 1440px and 375px.

## 6. One status board instead of scattered plans
**Problem:** seven-plus music-video plans in `docs/`, some superseded, and no single place to see where each video stands.

**Change:**
- `docs/music-videos/STATUS.md`: one table with columns song, slug, stage (idea → storyboard → stills ✔ → shots → render → YouTube → site), spend, YouTube id, and open questions. Update it at each gate.
- Per-video plans move to `docs/music-videos/{slug}.md`. Superseded plans get a one-line pointer.
- The `music-video` skill reads STATUS.md first and updates it at each gate.

## 7. Skill updates
- The pipeline steps reference `scripts/video.mjs`, `src/videos/{slug}/` and `kit/`.
- Add a **"new video checklist"**: folder scaffold (`node scripts/video.mjs new <slug>` copies a template: scenes.json skeleton, empty stills/shots, a composition stub that renders captions plus a terminal), STATUS row, registry entry, CHANGELOG.
- `references/site.md` shrinks to: "add the registry entry; the page builds itself."

## Order
1. **Item 1** (multi-song workspace), then the System Prompt regression check.
2. **Item 2** (kit), as Weight of Zero is built. Not a big-bang move.
3. **Items 3 and 4** (metadata merge and the `[slug].astro` page), then the build/HTML diff check.
4. **Items 6 and 7** (status board and skill), short.
5. **Item 5** when the Mac Mini is available.

Weight of Zero (`docs/2026-10-04-weight-of-zero-video-plan.md`) is the first video built on the new layout. Its stills can be generated as soon as Mark approves them, independent of this refactor.

## Not changing
- Generation tooling (`generate.mjs`, `analyze.py`, `transcribe.py`) beyond reading paths from the registry.
- YouTube upload flow.
- Public URLs.
